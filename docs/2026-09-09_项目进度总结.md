# 项目进度总结（2026-09-09）

> 全自动抖音追热点视频 Agent（线B 工程）。一句话：**抓热门 → 读懂它（模板/手法）→ 用素材库自动剪出成片 → 自己审片自己改**。
> 本文档是全项目总览；具体问题/取舍/诊断见 [README.md](README.md) 索引的各篇决策记录。

---

## 一、这个项目现在能干什么

| 能力 | 入口 | 状态 |
|---|---|---|
| 抖音热门视频→结构化模板 | 榜单/分享链下载 + 感知层（镜头/节拍/OCR/ASR）+ Omni 抽模板（三层防线） | ✅ 生产可用 |
| 外部信号补全热梗核心 | 标题/作者/评论区/相关视频进 prompt + 覆盖校验 | ✅（安琪拉/火影猫两轮验证） |
| 电影→镜头级可检索素材库 | ffmpeg 切镜头 → Qwen2-VL 结构化描述 → E5 语义索引（文本查询→镜头） | ✅ V0（预告片 593 镜头） |
| 热门卡点模板→自动卡点成片 | 模板节拍锁定切点 + 素材库检索轮换取材 + 白帧/模糊垫边 + 模板原声 | ✅（56 刀/25s，v3） |
| 成片自审自改 | Omni 看片出问题清单 → 确定性动作映射（换裁切/换镜头）→ 重渲 → 复审 | ✅ 闭环跑通（审美判断仍需帧级复核兜底） |
| 爆款片→剪辑程序逆向（Decomposer） | 信号轨→窗口问答→Recipe JSON→对比报告 | ⚠️ 首跑完成，图层手法还看不见（见"卡住"） |
| MiniMax 视频生成 | 自部署 H3（t2va/fl2va 首帧锚定/ref2va 已下未接） | 🧊 冻结（通用质量不足，转素材库路线） |

## 二、已完成（按时间线）

**1. 感知与模板（Phase 1-3）**：下载/感知基础件（幂等信封）；Omni runner（watch/ask/切片）；
模板抽取 + repair；安琪拉事件后接外部信号源（真核心在标题/评论区/相关视频）。

**2. 生成路线（Phase 4，已收敛为素材库服务）**：MiniMax-H3 服务器自部署三种工作流；
首帧锚定验证了跨 clip 人物一致性（紫发/全息战衣完全对齐）；安琪拉/火影猫共 6 条成片；
结论"通用生成质量不足"→ 用户拍板转固定素材库。

**3. 素材库主线（当前）**：荷兰弟三部曲 9 支预告片入库 593 镜头；检索架构用户拍板
VLM转文本+E5（不用 CLIP）；story→retrieve→assemble 出首片（13.4s，踩平帧率混杂三连坑）；
analyze_editing 学 6 条卡点模板共性（128BPM/每拍切/白帧 0.08s）；beat_cut 56 刀踩拍成片
v1→v2（critic 循环自动换模糊垫边）→v3（白帧减半/全动作检索/滤访谈镜头）。

**4. Edit Decomposer 基准（2026-09-09，技术核心）**：D1 确定性信号轨（亮度/差分/网格/光流
→8 类候选+contact sheet）→ D2 窗口级 Omni 问答（断点续跑/控制窗测漏检）→ D3 Editing
Recipe JSON（14 类枚举/证据锚定反编造/四档防线）→ D4 南昌原片 vs GLM 重剪对比+18 条人工验收清单。
**裁决：GLM"只会到点换画面"被证实（26 ops 全是切）；参考片 mask 填充/文字层手法全漏检
（帧级人审确认存在）——"editing operation understanding"这关没过，且被量化。**

**5. 工程底座**：228 单测全绿；problem-log skill（问题/方案对比/验证自动记录）；docs 11 篇；
本地写码→GitHub→服务器 pull 运行的单一事实源流程（含推送验证教训）。
