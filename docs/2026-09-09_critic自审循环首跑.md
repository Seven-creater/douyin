# 2026-09-09 critic 自审循环首跑（Omni 看片 → 改片 → 复审）

## 背景与问题

用户看完 beat_cut v1（center 裁切）反馈：布局/字体/比例奇怪，卡点做得还不错；
指令："设置一个让 omni 自己审核观看，然后知道自己哪里做得不好，然后进行优化"。

问题分解：①谁审、审什么维度 ②审出的问题怎么变成可执行修改（不让 LLM 直接改片）
③怎么验证"优化后确实更好"（critic 自己的判断可信吗）。

## 方案

| 方案 | 取舍 |
|---|---|
| GLM/LLM 只看描述改参数 | 无视听信息，审不了节奏/画面 → 弃 |
| Omni 看成片出结构化问题清单 + 确定性动作映射 | 审片用多模态、执行用代码（可测可回滚）→ **采用** |
| LLM 直接输出 ffmpeg 修改方案 | 不可控、难测 → 弃（与编辑分析同结论：策略归 LLM，执行归信号/代码） |

动作映射（critic.py derive_actions）：
- 布局类（aspect/crop_weird）≥2 处或含 high → 全局切换裁切策略 center↔blurpad
- relevance 带 t_s → 定位切序号（±0.3s 容差）重检索换镜头（排除已用）
- 其余（rhythm/transition/text_artifact/quality）记录进报告，V1 不自动处理

## 诊断依据（两轮审片实录）

- v1（crop=center）：score 2/10，5 个 high——crop_weird"人物头部和身体被严重拉伸和扭曲"、
  text_artifact 源烧录字幕、rhythm 踩点不齐、transition 生硬、quality 低。
  触发动作：crop→blurpad；relevance 换镜头 0 个（v1 未报 relevance 定位）。
- v2（crop=blurpad）：score 2/10，5 个问题——仍报"错误的横屏画幅竖屏播放，左右两侧被
  大面积裁切"；白帧转场"完全破坏音乐的节奏感"；室内对话/爆炸镜头与音乐不搭；烧录字幕；清晰度。

## 验证（关键：不信 critic 的自我报告，做帧级客观复核）

抽取两版 t=3s 帧 → 独立 VLM（4.5v）盲析：

1. **blurpad 确实渲染正确**：上下模糊垫边 + 中间完整横屏画面带（三人全部完整、无裁切拉伸），
   即抖音转发横屏影视的标准形态。→ v2 的"左右被大面积裁切"是**误报**——critic 把 letterbox
   观感本身当错误描述。教训：**critic 的画面类意见必须客观验证后再执行**（本次恰好切对了方向）。
2. **两版 t=3s 是同一镜头**：戴毛线帽女子面向镜头说话 + 繁体烧录字幕"這個爛攤子也是你搞出來的"
   + 废弃建筑场景三人对话。→ relevance 批评属实且根因可溯源：
   ①QUERY_POOL 里自己有"动作：对话；场景：室内"查询句（自己招来的）；
   ②预告合集（BV1Fx411U7bR）含低运动对话/花絮类镜头，索引未过滤；
   ③检索只看语义相似度，无"运动量/有无烧录字幕"权重——卡点混剪恰恰需要高运动画面。

## 结果分析

- score 2→2 没涨，但**画面客观改善**（主体从被裁拉伸 → 完整居中）——单一 critic 分数不可作为
  优化收敛判据；帧级证据 + 分维度问题清单才可靠。
- 白帧批评首次出现且合理：56 刀全打白帧确实过密（模板手法分析说"白帧 0.08s"，但模板并非每刀都打）。
- 循环机制本身工作正常：审片→定位→换策略→重渲→复审→双版报告全链路一次跑通。

## 残留风险

- critic 对"节奏"类判断无 ground truth 可复核（踩点由 librosa 节拍锁定，白帧落在切点上，
  它仍报"不齐"——可能是观感问题也可能是挑剔）。
- 单模型审美偏差：把行业标准的模糊垫边当"错误画幅"。

## 下一步（v3 动作集，全部可确定性执行）

1. 白帧降频：只在强拍（节拍能量前 N%）或每 2-4 刀打一次；
2. QUERY_POOL 去掉"对话"句，全部动作化（摆荡/格斗/坠落/蛛丝…）；
3. 索引过滤：caption 含 访谈/采访/花絮/面对镜头说话 的镜头降权或剔除；
4. critic prompt 告知目标画幅策略（"竖屏 544×960，横屏素材用模糊垫边是预期形态"），
   消除 letterbox 误报；
5. 烧录字幕规避：段预处理底部裁 8-10%（crop=in_h*0.9）或检索偏好无字幕镜头。
