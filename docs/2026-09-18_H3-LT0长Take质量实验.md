# 2026-09-18 H3-LT0：S2 Long-Take 质量实验（用户 v2 矩阵）

> P0 感知过线后的第一个生成实验。核心转向：**Generation Unit ≠ 最终
> Snippet**——H3 一次拍完整事件长 Take（12s），Omni 后期剪 Moment。
> 本轮不做成片、只用 S2、H3-Q1 同世界重拍。

## 实验设计（用户两轮拍板）

1. **Recipe 矩阵 v2**（关键是补了 video_only 对照，才能归因）：

| Recipe | 条件 | 回答 |
|---|---|---|
| A prompt_only | P0 派生 base brief | H3 裸能力 |
| B canonical_only | + C0×2/C1/arena 图 | 图片身份锚有无帮助 |
| C video_only | + 完整 S2 **静音**视觉参考 | 参考视频本身多强 |
| D canonical_plus_video | 图片 + 视频 | 图片锚能否在视频上增益 |

   First Frame 是第 0 帧端点约束而非语义参考 → 移 LT0.1。
2. **seconds=12**（参考 11.6s 匹配；15s 续写已结束事件，测不了真问题；
   12 vs 15 时长退化单独实验）。
3. **aspect 由 ffprobe 实测映射最近合法值**（禁写死 16:9、禁 auto——
   SGLang auto 会 fallback 16:9）；8 条同比例。
4. **视频参考一律 `-an -c:v copy` 静音版**：H3 会把带音轨 video 的音频
   当参考——不静音则 C/D 混入音频变量。音视频对比留后续。
5. **Canonical pack 候选制**：每 role 5 候选帧 + contact sheet，plan-only
   人工选 1（防八条实验建立在糊帧上）；同一 pack 复用全部 Take。
6. **跨 Take 身份对 canonical 锚比**（不链式比，防 A→A'→A'' 漂移链）；
   5 采样帧（10/30/50/70/90%），blurred/back_turned/absent →
   c0_match=null（可见性不足不判失败——高速运动误杀防护）。
7. **三分离评估**（VBench 思想，partial success 不丢）：
   quality（一致性/artifact/motion/跨 Take 身份）× coverage（4 phase
   齐全+顺序+moment 选择）× editability（≥3 段、总时长≥5s）。
   质量好但缺 phase 的 Take 仍可进素材库。
8. 所有 recipe 共用同一 base_event_prompt，只叠加 reference 子句；
   seeds 1001/1002 严格配对跑 A-D。结论仅适用 same-world resynthesis，
   跨身份迁移（LT1/Q2）另测。

## 实测

- 首轮 plan-only（53a7e8c）：aspect 实测 9:16——禁写死 16:9 的判断被
  证实（竖版参考）。人工审核 p0510 判定框架可用，但给出四项执行前修正。
- **四项修正（672318c+88b003a）**：
  1. canonical 目标裁剪（黑边之上：identity→头肩、fullbody→右半 C0、
     c1→左半 C1）+ **Arena 移除**（候选全是"垫+两人+裁判+观众"群像，
     不能当纯场景参考；场景由 prompt/Video 1 定义）；选帧支持
     `candidate_NN` 编号。
  2. **黑边归一**：服务器 ffmpeg 4.2.7 不打印 cropdetect 行 → 灰度
     原始帧纯 Python 逐行判黑（行均亮度<24），多帧中位；canonical 帧
     与静音参考全部裁到有效画面；**aspect 按有效画面算：720×1280 容器
     →720×1018 有效 → 3:4**（8 条同比例，全部像素生成有效内容）。
  3. **官方 H3-Context-IR 六段 prompt**（subject_definitions/summary/
     retention_analysis/detailed_description/overall_soundscape/
     non_diegetic_music）：`<Subject 1>` 由 Picture 1+2 联合定义、
     `<Subject 2>` 由 Picture 3 定义（官方 Ref2VA Guide 语义）；
     语义 phase 压缩（4 个 reflection shots→1 行，时间箱 0-2/2-7/7-9/
     9-12）；"一镜到底"改为"完整时间连续事件，允许自然机位变化，禁止
     换场景/换比赛/换人物"。
  4. **A 组走 fl2va server**（t2va、零条件），B/C/D 走 ref2va；报告将 A
     标注为 T2VA baseline（非同 checkpoint ablation），干净 ablation 是
     B vs C vs D。
- **plan2（49340bc）**：aspect=3:4（有效 720×1018）、C1 按人工编号选
  candidate_05@7.12、8 条 wire payload 全部落档并随审核包分发
  （data/lt0_plan2_review/，含 takes/、candidates 时间戳表、裁剪后
  contact sheet、裁剪+静音参考视频）。D 组 payload 与官方示例逐段对齐。
- 测试 771 绿。
## LT0 最终结果（2026-09-19 全 8 条收齐，预算修复后离线重算）

| recipe | takes | quality | coverage | editability | moments |
|---|---|---|---|---|---|
| A prompt_only | 2 | 2/2 | 2/2 | 1/2 | 1+4 个/条 |
| B canonical_only | 2 | 2/2 | 2/2 | 1/2 | 3+2 个/条 |
| **C video_only** | 2 | **2/2** | **2/2** | **2/2** | 3+3 个（9-10s） |
| **D canonical+video** | 2 | **2/2** | **2/2** | **2/2** | 3+3 个（9-11s） |

- **8/8 全部质量门通过**（主体/对手/场景一致、零严重伪影、动作 natural）；
  **跨 Take 身份对 canonical 锚 8/8 True**——包括 A（纯文字）与 C（无图片）。
- **C≈D**：same-world 下完整参考视频已把身份+事件锚牢，canonical 图片条件
  无可测增量 → same-world dailies 用 C（精简条件）。图片锚的价值要到 Q2
  （换人物、视频参考携带"错误身份"）才会显现——那是 LT1 的题目。
- B 图片-only：质量/覆盖全过但可剪 moment 数不稳（s1002 仅 2 段）；
  A 纯文字意外地强（六段式/三字段官方 prompt 的功劳），但 s1001 只 1 个
  长 moment，可剪性同样不稳。
- 诚实边界：n=2 seeds、单次观察、Omni 当裁判——方向性结论，非统计显著。
- 全程踩坑三连（均已修+入回归）：serve 脱离 conda PATH 找不到 sglang 二进制；
  ref2va setup 必传 num_frames；Omni 身份回答会幻多采样行（容忍越界行、
  要求全覆盖）。另：t2va take 首轮观察即发现"C0 只在前段出现"——观察层
  有效。
- 单条成本：12s@768×1024 ≈ 75 分钟（~10s/帧）；随后按用户要求实现
  **8 卡 4 实例并行**（每实例一对卡 + 独立端口，任务跨车道分发；resume
  前置——全复用轮不再起服）。

## execute 基础设施实录（两次尝试暴露的真缺口）

  1. `serve_h3.sh` 裸调 sglang（脱离 conda PATH）→ 已修（显式解析 h3 env 二进制）；
  2. **决定性发现**：已装 sglang 0.5.10.post1（PyPI 最新）**不含 MiniMax-H3
     管线**（multimodal_gen registry 仅 Hunyuan/Flux/Wan/ZImage/GLM/LTX/MOVA）；
     H3 支持只在上游 main。PyPI 无含 H3 的预发布。源码装 main 需
     **cu13 栈**（cuda-python≥13 / flashinfer[cu13] / humming-kernels[cu13] /
     torch 2.13），而服务器驱动 575.57.08 上限 CUDA 12.9（cu13 需 ≥580；
     升驱动=管理员+全机停机，2-5 卡还有用户自己的 vllm）——**SGLang 路线
     驱动级阻断**。P5.1 当时只做 CPU dry-run，此缺口从未暴露。
  3. **Ref2VA 权重缺失**（本地仅 FL2VA）：hf-mirror 可达（huggingface 直连
     不通），144.1GB/81 文件已挂后台下载（setsid nohup，`hf download`——
     huggingface-cli 已废弃不工作）。
- **路线拍板（用户）**：先探 SGLang main，装不上降级 diffusers → 探针结论
  =驱动阻断 → **走 diffusers**：官方 H3 repo 本身是 diffusers 布局
  （model_index + FL2VA/ + Ref2VA/ + transformer_ref/），h3 env 的
  diffusers 0.40 已实证跑通 FL2VA serve；下载完成后复用官方 scripts/
  的 Ref2VA 推理示例，包一层 /v1/videos 协议 serve 对接 SGLangH3Client。
  LT0 实验设计/产物全部不变，只换 serving 层。
