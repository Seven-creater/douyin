# 2026-09-12 C3 看片审计：字幕带定量 + 渲染缓存键缺口修复

## 背景

V3 终验收后人工看片 lxh_p4_V3_C3（「你来检查看一下」）。4-agent 工作流逐帧
审计 11 帧（data/preview/decomposer_d1/c5f/）+ 本地 OCR/黑边定量，两个结论：

1. **文案烧录本身工作正常**：钩子「人类从不真正接纳妖怪」0.15~4.2s 可见；
   卡片 1s 太薄夹在 2s 采样帧之间；punchline 21~21.95s 超出末帧采样点——
   之前"看不到文案"是采样/审计盲区，不是渲染缺失。
2. **真 bug：电影内嵌字幕没裁掉**。manifest 里 crop=iw:ih*0.88 ×3 都在执行，
   但字幕仍在成片里，且与自烧文案同在底部同风格（审计 agent 一度把钩子
   文案误分类成 movie_subtitle——两层文字打架的直接证据）。

## 定量定位（VLM 不可信，OCR 作数）

先用 analyze_image 问三张裁切变体（0.85/0.90/0.94），三份位置估计互相矛盾
（"85% 高度处" vs "92~98% 区域"）——**VLM 的坐标估计不能当测量工具**。
改用本地 RapidOCR + 行亮度扫描：

| 测量 | 结果 |
|---|---|
| 源帧字幕带（4 帧一致） | 距底 **16.7% ~ 21.1%**（顶部 78.5~78.9%） |
| 源片黑边 | 2.39:1 画面镶 16:9 容器：上 12.3% / 下 12.7% |
| 成片残留字幕（11 帧） | 顶部 90~96%（= 源裁 12% 后仍留大半） |

**根因**：`crop_bottom: 0.12` 是拍脑袋值——只裁掉了下黑边（12.7%），字幕带
（16.7%~21.1%）整个在保留区。要裁干净需 >0.211。

## 修复

1. **config/default.yaml**：luoxiaohei1/2 `crop_bottom 0.12 → 0.23`
   （字幕顶缘 0.211 + 2% 余量防双行字幕）。
2. **renderer.render_cache_key + subtitle_crops 参数**：裁切串是 vf 链一部分，
   必须进缓存键——否则改配置后旧段（带字幕）按 sha 命中被静默复用（本次
   险些发生：render_cache.json 只含 recipe/theme/画布）。render_recipe 调用
   处按槽算 `source_subtitle_treatment` 传入。
3. 渲染链本身无需改：前置 crop 后接 cover-crop（force_original_aspect_ratio
   =increase + focus_x 横向取景），裁 23% 只多裁两侧，无纵向变形。
