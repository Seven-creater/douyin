## 选择与理由（用户拍板 B）

1. **迭代式边界对账（reconcile-until-stable）**：每个内部边界先过确定性规则
   （下一 Section 首 shot 报 same_event 即事件内部→直移），否则抽边界前后各
   三帧（±2/±1/±0.4s）做画面级**三维度**判定：event 连续性 /
   rhetorical_function 连续性（提出命题 vs 提供反证 vs 扩展证据 vs 收尾打趣）/
   audience_cognition 连续性，prompt 明示"同主题≠同事件"。不成立→移到下一
   候选边界→**复查新边界**→直到真实语义变化或候选耗尽（BLOCKED），最多
   RECONCILE_MAX_ITERATIONS=4 轮。移动后受影响 Section 重看。
2. **候选切点全量交作业**：`_observe_section` 新增硬校验——输入
   cut_candidates_to_assess 的每个 boundary 必须出现在 cut_assessments
   （real_cut/not_cut/uncertain 三选一），缺失即 V9Blocked
   `cut_assessment_missing`。"18-22 秒被吞成一个 shot"从此不可能静默发生。
3. **转场身份保持**：`apply_montage_reclassification` 重写——转场永远是
   transition，逐镜头观察只补 transition_type 与 overlay_text 属性
   （转场期间挂字幕=叠加层，不是内容）。删除升回内容镜头的逻辑与
   `_aligned_montage_for_payload`（id 天然稳定）。
4. **snippet 结构对齐**：蒙太奇类模式（micro/event_compression/evidence/
   multi_angle/contrast/text_led_montage）的 snippet_count_range 程序侧强制
   `[max(2, ceil(0.6n)), n]`（n=观察到的内容镜头数，记录 basis）；requirements
   新增 reference_content_shot_count / reference_transition_count；validator
   加"蒙太奇 snippet 下限≥2"硬规则。
5. **Hook 命题保全**（用户第五条）：CONTENT_PROGRAM_PROMPT 新增
   hook_text_quote——第一个含屏幕文字的 Section 必须逐字引用断言文字并在
   takeaway 中呈现为全片待检验命题，不得降级为人物介绍；validator 逐字校验。

## 从结果学到什么

1. **确定性信号必须有权威**：same_event 是复看层亲眼所见的事实，模型的对账
   判断只能被它否决，不能反过来（P0.2 教训的延续）。
2. **移动一次不叫收敛**：任何边界修改都必须复查新边界，直到稳定——
   单步修复在结构问题上只是把错误挪了个位置。
3. **双重属性用字段表达，不用类型翻转**：转场+叠加文字是
   `segment_kind=transition, overlay_text=...`，不是"变成内容镜头"。
   类型翻转会摧毁下游对结构的全部计数（snippet、镜头数、节奏）。
4. **数量契约要双向锚定**：参考侧记 reference_content_shot_count，生成侧记
   target_snippet_count_range，两者失配在 validator 一眼可见。
