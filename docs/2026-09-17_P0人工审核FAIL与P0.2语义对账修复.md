## 选择与理由（用户拍板 C：P0.2 — Semantic Reconciliation & Edit Decomposition Repair）

不推倒 P0，只加层。新流水线：

```
Evidence → Global Watch → Sections → Section Rewatch
  → [新1] Section Boundary Reconciliation（边界两侧仍同一事件→移动到模型指定的
    第一个真实语义变化点，必须是既有 boundary；区间变化的 Section 重看）
  → [新2] Shot Normalizer（real_cut 必须成为镜头边界；确定性，纯代码）
  → [新3] Transition Segment Resolver（<0.30s 且两侧有内容的段=转场段，
    不再要求信息增量；类型由逐镜头观察补齐）
  → [新4] Semantic Conflict Gate（全局/复看/探针三源陈述对账→实质矛盾触发
    中立复核（只看局部画面、禁赛事分类名）→仍矛盾则 unknown+must_not_assert 禁词）
  → 快速蒙太奇逐镜头观察（触发段逐 shot 抽起/中/尾三帧单独看；带实义屏幕文字的
    转场段升回内容镜头）→ Probes → Conflict Gate → 三 Program → 人工审核
```

配套硬规则（全部入 validator + 回归测试）：
- 内容镜头>1 或有内部真切点 ⇒ 禁 continuous_clip（错误 2 的直接死因）；
- 边界无 reconciliation 依据（semantic_change 且非 moved）⇒ FAIL（错误 1）；
- must_not_assert 词条出现在任一 Program ⇒ FAIL（错误 4）；
- 最后 Section 有屏幕文字 ⇒ final_text_quote 必须逐字引用（错误 5 的机器侧兜底）；
- shot_refs 只准引用归一化内容镜头 id，转场段走 transition_refs（错误 3）；
- Editing Ontology 扩为 9 种 composition + 7 种 transition 类型（借 VEU-Bench
  的 editing-ontology 思路约束自由生成）。

## 从结果学到什么

1. **"机器规则全绿"与"理解正确"是两个命题**：validator 查的是结构合规，
   语义正确性目前只有人工门能兜——P0.1 的人工门再次证明必要。
2. **给模型的每个必填字段都是脑补邀请函**：强制"每 shot 必有信息增量"催生了
   转场帧的"沉思氛围"。确定性可判定的（时长→转场）交给代码，模型只答
   真正需要看的问题。
3. **两套平行数据结构（shots vs cut_assessments）必须有交叉校验**，
   否则下游编译器会挑结构最简单的那套自圆其说。
4. **上游分段错误会污染全部下游**，且复看层"看见了"不等于"能改"——
   修正权要显式设计成工作流阶段，不能靠下游自觉。
