# 2026-09-08 卡点模板分析 → 蜘蛛侠卡点成片（手法学习闭环）

## 背景与问题

用户路线：搜热门卡点/漫剪模板 → Omni 看懂怎么剪（含音频处理）→ 用这些手法剪素材库。
此前 GLM 版"照着剪"只有 16 个编辑事件且全是"到点换图"（PPT 感）。

## 候选方案（模板从哪来）

| 方案 | 实测 | 结论 |
|---|---|---|
| 抖音站内搜索 | 桌面版搜索无内容（要登录签名）、H5"页面不见啦" | 不可用 |
| Wellbyte 关键词榜 | `keyword=卡点` 返回 code=0 但 0 条（2 credits） | 不支持/无结果 |
| 分享页相关推荐点击雪球 | 点击落在标题展开，无导航无 ID | 不可用 |
| **B站热门搜索（综合排序）** | 卡点/漫剪/卡点混剪/踩点四词搜索+时长 15-120s 过滤，8 条候选 | **采用**（5 条下载成功） |
| 用户贴抖音分享链接 | 分享链下载链路现成 | 随时补充（南昌视频即此来源） |

## 途中两坑（诊断与验证）

1. **写盘四连崩**（另见专篇）：`write_result_json` 不建父目录，4 次 Omni 白跑。
   诊断：链日志"分析完成"但产物数=0；Traceback 指向 result.json.tmp FileNotFoundError。
   验证：修复后以**产物文件数 0→6** 为判定，非流程日志。
2. **JSON 截断两连败**（50s 高密度卡点）：3072 token 装不下逐拍 timeline。
   诊断：raw_answer.txt errors=['JSON 解析失败']×2 + 视频最长最密。
   修复：timeline 限 20 条代表性事件 + max_new_tokens 4096 → 一次通过（20 事件）。
   副产物：timeline 条数上限同时缓解了"自报密度与事件数不一致"的稀疏问题。

## 六条手法分析共性（Omni 看懂了什么）

128BPM 电子舞曲 / 每拍切（半拍切那条踩拍率 0.5 自洽）/ 白帧 0.08s 叠加切点 /
切点取节拍 / 结尾加速。→ **策略层与切点层分离**：切点用 librosa（确定性逐拍），
Omni 手法 JSON 只供策略（每拍 vs 半拍、白帧、音频风格）。

## beat_cut 实现与结果

模板节拍 → 每拍一刀（半拍策略自动细分）→ 10 类蜘蛛侠需求句轮换检索（E5 语义+
用过去重+时长约束）→ 0.47s/段统一 fps24 竖屏 → concat 重编码 → 56 个白帧切点
（drawbox enable between 单遍）→ 模板原声 BGM。

**结果（南昌模板）**：25.8s、**56 刀、0 占位**——对比原片 ~35 编辑事件、GLM 版 16。
189 测全绿。途中低级错 1 个（读信封漏 output 层，5 分钟定位修复）。

## 从结果学到什么

1. 卡点"手法学习"的正确分解是**策略（LLM 判读）+ 切点（信号检测）**两层，
   让 Omni 逐拍标注既贵又稀；
2. 监控永远盯产物数不盯流程日志（两坑同根源）；
3. 轮换需求句是无叙事卡点混剪的可用检索策略，但多样性上限受池子大小约束——
   正片入库后应换成"从模板自身画面生成查询"。
