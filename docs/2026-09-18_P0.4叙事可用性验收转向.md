## P0.4 实现（用户方案逐条落地）

1. **`src/agentic_video/narrative_boundary.py`（新模块，用户指定路径）**：
   有限叙事功能表 `situation_setup / problem_statement / counter_evidence /
   evidence_expansion / punchline_payoff`；LLM 只为边界两侧**选枚举**（描述
   层，枚举值无从编造/echo），`decide_narrative_boundary` 做字符串不等比较
   （决策层，纯确定性）。判定规则写死在 prompt：事件完整闭环（准备→对抗→
   结果→赛后反应）同属一个功能；新功能必须开启**新的表达目的**。
   - 5.1：problem_statement→counter_evidence = keep
   - 13.0：counter_evidence→counter_evidence（收尾反应仍是反证）= move
   - 16.7：counter_evidence→evidence_expansion = keep
2. **剪辑模式由镜头序列派生**（不再信 LLM 直判 continuous/montage）：
   continuous_clip 与真实切点矛盾时，同事件多数 → event_compression_montage、
   并列不同事件 → evidence_montage（basis=derived_from_shot_sequence）。
3. **Narrative Usability Validation**：validation 新增
   `narrative_usability` 五布尔（每 Section 有叙事目的 / 蒙太奇不被误读 /
   content-transition-overlay 分型 / 事实矛盾不悬空 / 素材需求可检索），
   任一 False = error；审核表头部改为功能对账（before/after 枚举逐候选展示）。
4. 版本：V9/RECONCILIATION 升 `_p04`。same_event 布尔保留记录（供模式派生，
   不参与边界决策）——事件判断从决策位降到数据位。

## 验收与放行（P0 退出标准，用户五条）

1. 每个 Section 有清晰叙事目的（Hook / 反证 / 证据扩展+笑点）；
2. 多镜头蒙太奇不被理解成 continuous clip；
3. content shot / transition / overlay 三型分明；
4. 不存在"一个模块说 combat、另一个说 poomsae 还 PASS"；
5. Material Requirement 换一部电影也知道找什么素材。

达成即冻结进入 H3 生成阶段；**不再追求边界秒点精度与"完美理解"**。
