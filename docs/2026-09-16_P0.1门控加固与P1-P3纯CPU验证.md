# P0.1 门控加固与 P1–P3 纯 CPU 验证

## 背景与问题

P0 已有参考视频理解代码，但真实 Omni 运行与逐段人工验收尚未完成。代码审查指出四条可能造成假 PASS 的路径：`unsupported` 证据消掉必答 Gap、重叠 optional Gap 覆盖 required、旧人工审核文件接受新 Program，以及 Edit Program 未证明直接逐段复看。后续 P1–P3 可以开发 CPU 契约，但不能把尚未验收的 V9 输出当真值，也不能因为假后端通过就解锁 H3。

## 候选方案

| 方案 | 思路 | 预期优劣 |
|---|---|---|
| A | 等 GPU 空闲后才继续 P1–P3 | 避免误用真实 P0 输出，但契约、编译器和状态机问题仍未提前暴露 |
| B | 先加固 P0 门，再用固定合成 fixture 独立开发 P1–P3 | 能分层定位并提前测确定性逻辑；不能证明真实语义质量 |
| C | 直接把现有未验收的 V9 产物送进 H3 | 看似快，但会把 P0 的错误传给生成，无法归因；未执行 |

本轮选择 B。P0.1、P1、P2、P3 分别提交，不将后一步测试结果回写成前一步验收。

## 实测/对比

- P0.1：补了四类假 PASS 回归测试；该阶段全量 `pytest` 为 **638 passed**。Commit：`d2aacad`。
- P1：固定 `S2` fixture 有 **2 个 Generation Units / 4 个目标 Snippets / 1 个 Section**；`unknown` 连续性、缺失因果目标、错误阶段划分均阻断。定向 **5 passed**。输出是 `v9g_p1_draft`，`execution_authorized=false`。Commit：`5d67b1b`。
- P2：三类资产命名空间、文件 SHA、来源区间、允许/禁止迁移及六段式 H3 提示预览；参考证据身份迁移、未提交 memory、变更文件哈希均阻断。定向 **7 passed**。输出仍 `execution_authorized=false`，只做 capability route 预览，不生成正式请求。Commit：`ca5f700`。
- P3：假后端链路的 Unit 1 原始片尾为右侧，采用 Snippet 在 `2.7s` 结束、状态为左侧；Unit 2 输入验证为左侧。Raw 未通过、裁剪未通过和身份连续性错误均阻断提交。定向 **5 passed**。结果名为 `FAKE_CHAIN_PASS`，并非真实生成 PASS。Commit：`2f8cefa`。
- 当前全量测试：**655 passed in 33.03s**。改动文件 Ruff 全通过；全仓 Ruff 报 **79 项既有问题**，未作为本阶段通过项。Python 3.10 解释器在本机不存在；使用 Python 3.13 的 `ast.parse(feature_version=(3,10))` 检查新增模块语法，并在当前解释器导入成功，**不等同真实 3.10 运行**。
- 真 Omni、H3、真实 Section Review、Requirement Transfer Test：**未测**，因为本阶段只做不占 GPU 的代码与假数据验证；没有生成或冻结真实三个 Program。

## 诊断依据

P0.1 四条路径的共同问题不是模型质量，而是验证器可把“执行过流程”误判为“获得有效证据”。所以把 supported evidence、Gap 严重度、审核文件与当前文件哈希、逐段原片复看引用分别变成可检验条件。P1 测试进一步区分了参考片的四刀与 H3 的两个主要因果动作 Unit，排除了“刀数直接决定生成次数”的隐式规则。P3 的 `2.7s` 与原片尾状态故意不同，直接区分“采用 Snippet 末端交接”与“Raw Unit 末端交接”两种实现。

## 选择与理由

- P1 只接受固定 fixture，产出不可执行草案；不从 P0 未验收产物自动签合同。
- P2 采用确定性模板搬运合同与白名单资产描述，而不是额外 LLM 自由改写，以便错误能归因到 Contract、资产、Compiler 或 H3。
- P2 资产选择只从 Unit 的 `condition_keys` 读取；不允许编译时临时塞入合同以外的参考资产。
- P3 仅为假后端状态机，允许清楚测试提交顺序，不宣称视频质量或真实条件有效性。

## 验证

判定本轮 CPU 工作完成的标准是：四条 P0.1 假 PASS 回归被阻断、P1 `Unit ≠ Snippet` 契约成立、P2 资产与提示对相同输入稳定且不转移参考身份、P3 Unit 2 接受的状态来自采用片段末端；相关测试已通过。**真实 P0 仍未完成**：必须真实 Omni 分析参考片、逐 Section 人工检查三个 Program、匿名 Requirement Transfer Test 全通过后，才能签署并冻结 SHA。H3 capability 与实际生成另设后续门，当前不得进入。

## 结果

本阶段交付了分层、非执行的 P1/P2 草案及 P3 假链路；代码通过 655 项全量测试。`P0_CODE_READY=true`，但 `P0_REAL_OMNI_ACCEPTANCE=pending`、`P0_PROGRAMS_FROZEN=false`、`H3_REAL_CAPABILITY=unverified`。没有真实参考分析 PASS，也没有生成视频。

## 从结果学到什么

门控应证明“证据支持结论”，而不是“相关工具被调用过”。生成 Unit 的尺度应按单一可控因果目标定，而不是按最终切片数量定。任何用于下一镜的状态都必须取自观众实际看到的采用片段末端；假后端测试能证实交接逻辑，但不能证实模型看懂画面或 H3 能遵守条件。
