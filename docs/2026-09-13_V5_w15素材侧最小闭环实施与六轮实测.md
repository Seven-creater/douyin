# 2026-09-13 V5 w15 素材侧最小闭环：实施与六轮实测

## 背景与问题

上一版 w15 粗剪虽然名义上从单窗启动，但通用 Story Planner 会重新搜索整部
电影，并套用 `assertion_visual_payoff` 四槽结构；最后使用的素材不再等同于
w15，`22s` 目标还可能被无意义画面补长。因此“w15 成功”不能证明单场景
素材链路成立。

本轮由用户拍板把目标缩成一个可证伪的控制实验：只允许使用
`luoxiaohei1` 的 `2965–3005s`，验证“人和妖不能简单按类别判断好坏”这段
内容能否经过真实定位、证据核验、渲染、双音频盲审和人工验收。明确不做
72 窗、Gap Watch、跨电影故事或 Film Bootstrap。

输入规模与基线：

| 项目 | 实测值 |
|---|---:|
| 4K 源片 | 12,698,126,065 bytes |
| transcript | 78,322 bytes |
| BGM `template_7682.m4a` | 355,918 bytes |
| 修改前本地测试 | 419 passed |

核心风险不只是“能不能导出 mp4”，而是六个语义契约能否同时成立：容器可跨
scope、最终证据不可跨；ASR 原段不可被窗口截断；相对时间必须有 origin；
22 秒只是软目标；两版画面必须物理相同；模型盲审不能替代人工终验。

## 候选方案

| 决策点 | 方案 A | 方案 B | 结论 |
|---|---|---|---|
| Scope 候选过滤 | Event 必须完整 contained | Event 只需 overlap，最终 evidence/render contained | 选 B；否则会误杀跨边界容器内的正确证据 |
| 时间坐标 | 只记 `absolute/relative` | 同时记 raw、input clip、origin、normalized absolute | 选 B；下游只消费 normalized 值 |
| Transcript | 整个 ASR segment 都是 required | immutable segment 与 required semantic span 分层 | 选 B；无法判定时才保守保留整段 |
| 时长 | 必须补满 22 秒 | `12–26.4s`，内容完整优先 | 选 B；禁止空镜填充 |
| 结构 | 通用四槽 | RoughcutSpec 显式 `setup/core_statement/response` | 选 B；可选阶段无证据直接省略 |
| 身份 | 强制 canonical 角色名 | 本场景 speaker/addressee 局部身份 | 选 B；本轮不绑 Film Knowledge |
| 双版本渲染 | 两次独立视频 render | 一次 Content Master，再分叉音频 | 选 B；用 frame MD5 验证画面相同 |
| 盲审主体门控 | 强制 `consistent_protagonist=true` | 粗剪门控局部 speaker/addressee 与核心复述 | 最终选 B；A 在 v4 产生假阴性 |
| 最终交付 | Omni 自动通过即 PASS | 自动候选 + 独立人工 acceptance | 选 B；用户明确要求人工是最终门槛 |

“Event 必须完整 contained”“ASR segment 等于 required evidence”“硬补 22 秒”
和“两次独立 render”均未继续做成正式实现：前三项已有边界反例，最后一项
无法物理保证逐帧一致，继续实测没有决策价值。

## 诊断依据

1. **v1 把“Omni 慢”排除为首因。** GPU 尚未开始 localize，进程却累计读取
   接近整部 12.7GB 文件；改用 ingestion SHA 后，后续轮次不再出现这段全片
   I/O，说明瓶颈在重复哈希而非模型推理。
2. **v2 把“电影内容不支持”排除。** verify 的 `what_is_visible` 已明确描述
   “好坏并非绝对”，失败只来自 absolute interval 被当 relative 再加 origin，
   因而根因是坐标归一化而非证据缺失。
3. **v3 把“BGM 文件缺失”排除。** 失败信息精确到旧 FFmpeg 不认识
   `amix normalize=0`；改成等价预增益后，同一服务器 source/BGM 派生 smoke
   成功。
4. **v4 把“盲看不可复述”排除。** 两个 summary 都描述人与妖及微妙平衡，
   speaker/addressee 稳定、对白清楚、BGM 可闻；唯一失败位来自另一个任务的
   protagonist 一致性，并且 switch 时间还越过实际片长。
5. **v5/v6 坐实最终数据流。** blind_v3 在不知道 Story Plan 的条件下，两版
   都复述了“好坏不是绝对的”；相似度 `0.9167`，而 frame MD5 完全相同，说明
   音频分叉没有偷偷改变画面。

## 选择与理由

最终选择用户拍板的“最小闭环优先”：RoughcutSpec 是唯一范围与结构来源；
容器只参与召回，真正出片的 evidence/render interval 才执行 contained；
Omni 原始时间和归一化时间同时留档；ASR 数据层与 required semantic span
分离；时长 fit 只压缩冗余，不裁 required evidence，也不为 22 秒填空镜。

渲染采用一个 Content Master，并显式抽取 `source_audio.m4a`。source_only
直接保留母版，bgm_mix 用母版视频 `-c:v copy`，只重做音频。旧 FFmpeg 的
兼容公式保留原声 1.0、BGM 0.25 的有效比例，同时不使用服务器不支持的
`normalize=0`。

验收采用两阶段：Omni blind_v3 独立复述、检查局部说话关系与不同音频条件；
自动通过后写 `automated_acceptance.json`，但仍以
`human_acceptance_pending` 阻断。人工确认使用 `roughcut-accept`，该命令会
重验母版、源音和两版文件哈希；只有确认通过才复制 BGM 版为根目录
`rendered.mp4`。

## 结果

V5 w15 的**工程最小闭环已经跑通到人工终验前一关**：范围、证据、定位、
验货、时长、字幕、唯一母版、源音/BGM 分叉、逐帧一致和双版自动盲审都有
真实产物与哈希。最终 v6 位于：

`/data02/usr/wangqihao/Demo/research/data/agentic_runs/lxh_v5_w15_minloop_20260913_v6`

当前不能宣称最终 PASS。真实状态是自动门控通过、人工尚未观看，故
`delivery=blocked`。人工需要分别观看：

- `variants/source_only/rendered.mp4`
- `variants/bgm_mix/rendered.mp4`

并确认能够复述核心判断、两版对白清晰、BGM 版确有音乐。确认 JSON 示例：

```json
{
  "approved": true,
  "story_in_one_sentence": "两人讨论人和妖不能简单按类别判断好坏",
  "source_only_speech_clear": true,
  "bgm_mix_speech_clear": true,
  "bgm_mix_music_present": true
}
```

然后执行：

```bash
python -m src.agentic_video.cli roughcut-accept \
  --output data/agentic_runs/lxh_v5_w15_minloop_20260913_v6 \
  --human-acceptance <人工验收.json>
```

若人工拒绝或任一音频条件未确认，仍保持 BLOCKED，不生成正式文件。

## 从结果学到什么

1. **范围约束应落在可消费证据，而不是索引容器。** 索引 Event 是召回容器，
   把 contained 提前到候选层会系统性漏掉边界证据。
2. **所有模型时间都必须带观察区间与 origin。** 只存 `relative` 标签无法审计，
   absolute/relative 混用会让“内容正确”被判成“证据越界”。
3. **模型推理前的全片 I/O 也属于关键路径。** 大文件哈希应由 ingestion
   manifest 负责，消费阶段验证 manifest，不重复读取 12.7GB。
4. **失败类必须指向真正层级。** v2 是 verification，v3 是 audio，v4 是门控
   契约不匹配；如果统称 content unsupported，会把修复方向全部带偏。
5. **不同任务不能复用同一个“主体一致”布尔门。** 多场景故事关心 protagonist，
   单场景对白关心 speaker/addressee 和核心判断；原始盲审字段应保留，但门控
   必须匹配实验问题。
6. **自动盲审是独立证词，不是人工验收替身。** 本轮即使模型复述相似度达到
   `0.9167`，仍不自动发布；这条约束应保留到后续 72 窗实验。
7. **下一阶段仍不应自动扩大到 72 窗。** 先由人完成 v6 双版观看并落
   acceptance；只有人工也能稳定复述，才具备讨论 Gap Watch 和全片创作的前提。
