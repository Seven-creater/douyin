# 2026-09-09 Edit Decomposer 基准首跑（D1-D4 全链路 + 南昌原片 vs GLM 重剪对比）

## 背景与问题

分析文档（用户重提）的判断：GLM 重剪"PPT 感"的根因不是卡点（100% 对齐）而是
**editing operation understanding 缺失**（mask 填充/遮挡转场/文字层/速度变化），
并点名"这一关过不了，后面搜一万个素材都没意义"。本轮把 2026-09-07 搁置的
Decomposer 计划按现状升级后实施：D1 确定性信号轨 → D2 窗口级 Omni 问答 →
D3 Editing Recipe 合成 → D4 两片对比报告+人工验收清单。

## 方案（各层取舍）

| 层 | 方案 | 取舍 |
|---|---|---|
| D1 证据 | ffmpeg 单遍灰度解码 + numpy/cv2 指标（亮度/差分/6×6 网格/Farneback）→ 8 类类型化候选 | 物理证据不可被 LLM 编造；高召回低精度，精度交给 D2 |
| D2 判读 | 候选 ±0.6s 开窗，Omni 看窗答 1 个 JSON（fps 8） | 1.2s 窗 ~10 帧（感知 2fps 不够）；每窗独立信封断点续跑；控制窗（信号谷底）测漏检率 |
| D3 合成 | 规则底稿（零编造）+ LLM 合成 + 校验/repair/剪枝/回退四档 | op 级错误剪掉坏操作接受剩余（≥半），段级错用确定性边界重建 |
| D4 报告 | 指标对照+直方图差+18 条人工验收清单 | 清单含"Decomposer 未主张"的漏检对照项——基准可信度关键 |

## 诊断依据（四连修实录，全部服务器首跑暴露）

1. **竖屏 reshape 崩**：工作宽 272 不被网格 6 整除 → 宽高按行列取整。
2. **巨窗**：0.3s 间隔密集候选链式合并滚出 0~8s/11~24s 窗（单窗单答丢粒度）
   → max_window_s=2.5 关窗另开；顺带发现模型报片段内相对时刻 → prompt 加时间换算。
3. **整包回退不公平**：GLM 版 1 个残留错误 → 63-op 光流噪声底稿 → 加剪枝档。
4. **JSON 解析失败×4 的真根因**：模型把 63 个信号候选逐条转写，12KB 输出仍截断
   → 上下文候选行限量 top30+类型保底后**一次通过**。
   连带发现：①radial 分数没除以光流模长（-6.78 越界 [-1,1] → zoom 假阳性，
   已修未重跑）；②中间两次"修复重跑"跑的是旧代码——`git push && ssh pull`
   链式命令里 push 静默失败被 `| tail` 吞掉（16 分钟白跑；教训：**启动远端长任务前
   必须核对服务器 HEAD**）。

## 结果（两片全链路跑通）

| 指标 | 参考片（南昌） | GLM 重剪 |
|---|---|---|
| Recipe mode | json（1 次过，11 ops） | json（第 5 跑，26 ops） |
| ops/min | 26.1 | **61.8**（更密但全是切） |
| 类型构成 | 11 hard_cut | 15 hard_cut + 9 montage + 1 zoom + 1 match |
| 落拍率 | 63.6% | 61.5% |

## 结果分析（基准的裁决：这关**没过**，且被量化）

1. **GLM 版证实"只会到点换画面"**：26 个操作全部是切/连切，零图层手法——
   连 montage 都只是密集 hard_cut。
2. **参考片的 mask/文字层手法 Decomposer 全部漏检**：帧级人审（t=1.8 三帧）确认
   存在"主体剪影保持+内部掏空替换+文字层独立跳变"，但 Recipe 只有 11 个 hard_cut。
   根因三层：①窗口单答粒度把窗内结构吞成 hard_cut；②region 检测门槛（全局差分<10）
   被文字变化抬高而漏检；③电池无图层专项提问。
3. 控制窗有效：参考片 2/3 信号谷底窗发现真切点（信号轨漏检率的实测通道）。
4. ops 数 11 vs 26 与文档 35 vs 16 方向相反：参考片 LLM 过保守（宁缺毋滥过滤 53 个）、
   GLM 版转写多——**数量指标不可比，类型构成才是判据**。

## 残留风险

- radial 归一修复后 D1/D2/D3 未重跑（本轮结论不依赖 zoom 假阳性，后续跑新片生效）；
- 落拍率与文档 85.7%/100% 不可比（容差 0.15s vs 0.2s、节拍列表不同）；
- 人工验收清单（report.md 18 条）待用户填写——最终裁决权在人。
