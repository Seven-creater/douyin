# 2026-09-15 V8.1 三层感知漏斗诊断实验

## 背景与问题

V8 的 6 秒固定窗口曾产出 265 条可解析 JSON，但人工复核发现这些“成功”不能证明模型
看懂了完整事件：动作可能从窗口外开始，局部主体可能被误认，`visible verb` 一类占位文本
也可能通过旧 Validator。V8.1 因此不直接追求三角色成片，而是把感知拆成：

```text
Global Browse
→ 候选合并/去重
→ 可向两侧扩展的 Context Watch
→ native frame / PTS Fine Boundary
```

本轮只回答三个问题：A/B/C 浏览条件能否找到值得深看的区域；Omni 得到完整上下文后能否
正确描述局部主体、动作与结果；只有前两关可靠时，才判断事件数量是否足以支持接近参考
节奏的短片。不使用 YOLO、Ultralytics、Tracker 或专用 ReID；旧 V8 的 265 条结果只作为
失败样本，不进入新 Event Fact。

## 候选方案

| 方案 | 处理方式 | 取舍 |
|---|---|---|
| A：继续把 6 秒窗口当事件 | 旧窗口直接生成 occurrence/event | 成本最低，但边界截断和错误 JSON 已被实测证明会污染事实层，否决 |
| B：固定 `2fps+r0.10` 浏览后直接深看 | 只修 Omni 上下文 | 无法区分时间采样不足与压缩过强，否决 |
| C：A/B/C 浏览矩阵 + 可扩展 Context Watch | 2fps/r0.10、4fps/r0.10、4fps/r0.25 只比较候选；候选合并后用 4fps Omni 深看 | 本轮采用；能分离 Browse 与 Context 两层故障 |
| D：Context Watch 固定 12fps | 用高帧率理解 10–40 秒上下文 | 真机 15 秒输入额外申请约 14.79 GiB 并 OOM；12fps 应只用于窄范围边界，否决 |
| E：发现失败后把已知 5412 答案写进 Prompt | 用针对性提示修单个样例 | 会造成循环自证，未实施；保留身份中性、答案隔离的诊断合同 |
| F：Pilot 未过仍继续 Identity/Planner/Renderer | 先尝试产片再看结果 | 会把浏览与事实错误传到身份和成片，按用户批准的门控禁止 |

实现选择 C，并把 ReferenceTask 的时长、有效单元数、section/shot 分布作为 Planner 的软
偏好；内容完整可短于参考时长，禁止 filler。Fine Boundary 使用源片真实 FPS/PTS，不写死
60fps。

### Context Watch 与人工逐帧检查

28 个合并候选共执行 47 次 4fps 请求，全部采样审计通过；每次 40–104 帧。最终 22 段
`observed`、6 段失败、0 段 partial、0 段 unreliable，生成 75 个 occurrence 和 55 个
event candidate。失败分布为：重复语义字段 1、event 引用缺失 patient occurrence 1、
invalid JSON 2、30 秒扩展时 OOM 2。OOM 归为 infrastructure，不解释成内容不存在。

`5412.3–5419.0s` 回归段自动扩为 `5410.65–5424.65s` 并报告边界完整。人工接触表明确
显示：白色小个主体约在 `5412.6s` 抬手，紧接着深色主体飞出并落地。Omni 虽看到了三个
局部主体，却把白色主体描述成“躲在后面、害怕”，把深色受影响主体写成 `actor`，动作是
被动的“is thrown through the air”，没有恢复施动关系。增加上下文解决了“前因未输入”，
没有解决“看见后理解错误”。

进一步检查接触表还确认至少 5/22 个可解析响应存在确定问题：不存在的爬树动作、重复事件、
5412 施动方向错误、自相矛盾的承载关系、把切到近景当作主体事件。即使其余 17 个全部
正确，具体可复述事实通过率上限也只有 **17/22 = 77.27%**，低于 90% 放行门。

## 选择与理由

保留三层漏斗和严格 Validator，不因模型已返回 JSON 就降低门槛。理由是本轮已经分离出两
个先后故障：Browse 三组共同低召回；即使人为强制加入 5412 回归段并给 Omni 足够上下文，
Context 层仍把受影响者当施动者。继续做 Identity、Planner 或 Renderer 只会掩盖首次故障。

没有根据已知剧情改写 5412 Prompt，也没有把“小黑”“击败”“战斗结束”写入中性答案。
人工只检查可见的局部主体和时序关系，保持 `Occurrence ≠ Character`。A/B/C 等低召回时
也不选择 A 作为“充分方案”；A 只能说成本最低，不能说感知足够。

并发仍保留，因为从串行约 7 分钟只完成 3 段，改为四路后干净批次约 15 分钟完成 28 段
及 19 次重试/扩展。并发 ID 污染被独立测试捕获并重新干净运行，不能复用污染结果。

## 从结果学到什么

1. Global Coverage 100% 只证明时间轴被粗看过，不证明关键微动作被发现；Coverage 与
   Candidate Recall 必须分开报告。
2. A/B/C 等低召回不能推导“最低成本 A 足够”。只有达到预设充分阈值时，等结果才允许按
   成本选 A；否则应归为共享模型/Prompt 瓶颈。
3. 4fps/r0.25 增加唯一候选但 GT recall 不变，说明本轮首要问题不是简单提高 fps 或
   retention，而是浏览语义、时间定位或基础 VLM 对微动作的识别。
4. `left/right_context_complete=true` 只表示模型认为输入边界完整，不证明动作因果正确；
   5412 回归段必须保留为 actor/patient 方向测试。
5. occurrence-first 还需要明确区分 initiator、affected subject 和状态主体。把“被抛飞者”
   填进 `actor_local_id` 会在身份绑定前就污染 Event Fact。
6. 生成时停止在第一个完整 JSON 能解决重复输出和 token 拖尾，但不能修复内容幻觉；结构
   合同通过与事实验收是两道独立门。
7. Context 的常用 20 秒不能是语义墙。本轮确实扩到 23/30 秒；无法承载时必须记为 OOM
   infrastructure，而不是伪装成素材缺失。
8. 并发优化必须测试数据归属，不只测试吞吐。批量请求若仍引用旧循环变量，会让正确视频
   结果挂到错误 Context；运行中的旧文件也不能用于进度验收，必须以最终 manifest 为准。
9. 下一轮应只修两件事：提高 identity-free 微动作候选召回，以及把中性事实 schema 改成
   initiator/affected/state-change 可独立表达；在这两关通过前，不应重新启动三角色成片。
