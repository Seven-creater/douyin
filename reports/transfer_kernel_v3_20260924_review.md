# 实验：跨题材关系抽象 v3

## 1. 任务要求

### 1.1 总目标

在不重新观看参考视频、不改旧生产链的条件下，把已核查的私有 `reference_intent_v1` 转换成可跨题材创作的公开简报。原片事实与表达目标须分开；原片人物、字幕、证据 ID 和媒体路径不得进入主题请求。

### 1.2 验收

沿用开发回归 C01–C04：两个跨题材同关系正例接受，两个关系／立场不同负例拒绝；来源审核和跨领域审核均通过，才签发 `trial_acceptance_v3`。失败时可以生成恰好三个隔离的 `unverified` 主题预览，但不得进入故事或生产。四例是开发集，不是封存泛化测试。

输入固定为参考媒体 SHA256 `2f95e24edd2cf4b79cc1f40f7e202174c53a6abcf084e728bb49e3ca92938a17`、私有主旨 SHA `923666dfb6011be1d042f3213b88795a056b7d23abc84ea507dc4c0ae13ed885`。8 例评审器校准在相同模型配置、提示词和样本 SHA 下复用先前两次乱序运行，均为 8/8；本实验没有新的全片视频调用。

## 2. 实际做法与进展顺序

### 第一步：实现隔离接口

新增 `transfer_kernel_v3`，私有层分别记录原片具体主张、跨领域表达目标、各故事单元的原片绑定／近层概念／叙事功能／观众效果和关系。公开 `creative_story_brief_v3` 只从跨领域层白名单构造；`trial_acceptance_v3` 绑定父产物及审核 SHA。旧 v1/v2 接口和生产 DAG 未修改。新增单次私有 grounding、单次逐字段 portability 审核，并复用现有字段映射与立场评审器。

### 第二步：本地与服务器验证

本地 `python -m pytest tests -q`：**1112 passed，1 skipped**（最终代码 `d72312e`）。服务器的 `omni_src` 环境可导入 v3 入口，但未装 pytest；真实模型调用在独立 worktree 运行。`run_001`、`run_002`、`run_003` 分别保留 **26、31、55** 个原始文件；最终 `result.json` 本地与远端 SHA256 同为 `2aeb36e9d3bff7fe660235695aa48f7eea6ed2b09316c90e6a1edbf91de16cc6`。

### 第三步：有界文本对照

`run_001` 完成 kernel 和 grounding，portability 输出路径格式及字段覆盖不符合契约，停止。`run_002` 的 portability 完整覆盖 12 字段；四例映射的 JSON 恰好在 4096 输出 token 上限截断，停止。两轮均保留原请求、原始响应和失败文件，未当作语义评测结果。

`run_003` 只把映射调用上限增至 8192 token，提示词与评测案例不变。实际 **8 次新文本调用**，合计 **10,694 input tokens、8,824 output tokens、635.64 秒**；未重试单层调用。完整请求、原始响应与模型元数据位于 `run_003/calls/`、`run_003/themes/` 和 `run_003/theme_critique/`。

## 3. 出现的问题与解决过程

### 3.1 抽象接口仍把原片题材当成不变量

**现象：** `run_003/public_brief_draft.json` 的 `roles.U1.audience_effect` 仍写“失去双手”所引起的观众判断。Portability Audit 在 12 个字段中将这一项明确判为 `source_domain_required`；其余 11 项判为 `portable`。

**根因：** 这是模型生成的语义残留，不是文件路径或原字幕原文的字面泄露。白名单只能限制字段来源，不能保证进入白名单的自由文本已达到跨领域抽象层。

**解决：** 独立 portability 审核按完整字段逐项检查，发现该残留后阻止正式简报和凭证发布；不据此即时改写答案。

**验证：** `run_003/portability_audit.json` 指出具体字段；`run_003/result.json` 为 `unverified_preview`，不存在 `creative_story_brief_v3.json` 或 `trial_acceptance_v3.json`。

### 3.2 两次执行契约错误未冒充语义结论

**现象：** `run_001` 的 audit 路径使用斜杠且漏掉 `audience_effect`；`run_002` 的映射输出 token 数恰为 4096，最后一条 JSON 未闭合。

**根因：** 首次 audit 请求没有显式提供需审字段的准确路径清单；四例 × 12 字段的映射输出超过了初始上限。这两项均由原始响应确认，不是四例语义分数。

**解决：** 输入审计字段清单，要求原样返回全部 dotted path；映射上限由 4096 提至 8192。每次重新执行均使用新 run 目录。

**验证：** `run_003` 的 12 个 portability 检查全部可解析，映射 JSON 完整，实际映射输出 **4147 tokens**；提示词和开发案例标签没有因此改动。

### 3.3 正例退化与预览主题的错误绑定

**现象：** v2 冻结基线为 **3/4**（仅 C02 拒绝）；v3 为 **2/4**（C01、C02 均拒绝，C03、C04 正确拒绝）。C01/C02 都因 `roles.U1.audience_effect` 的“双手”限定失败；C02 还因 U4 的普通局限与 R3 的收束关系未被映射而失败。三个主题预览都留在身体障碍范围内：T1 甚至再次使用“失去双手”；主题模型把 U1–U4 的叙事单元 ID 绑定为不同人物，而不是同一故事中承担不同信息功能的单元。

**根因：** 前半句是逐字段评审的直接结果。后半句是由 `theme_batch.json` 推断出的接口歧义：`role_bindings` 给出了角色 ID，却没有阻止模型把“叙事角色”理解成“人物角色”。此外，U4 的收束功能在公开简报中仍是硬映射字段，而本轮约定故事结构应为软偏好。

**解决：** 本实验没有继续针对四例改提示词或更改标签；按既定门槛停止发布，三个主题仅作为失败诊断的 `unverified` 预览。

**验证：** `run_003/contrast_mapping.json` 给出 C01/C02 逐字段失败理由；`theme_batch.json` 保留三个原样主题。`source_copy_audit.json` 对 T1 标 `surface_copy=false`，理由却明确说它直接复制“失去双手”，构成同一响应内的矛盾；所以不能把该审核视为原创性已通过。

## 4. 简洁实验报告

### 4.1 主要结果

| 项目 | 冻结 v2 `run_003` | v3 `run_003` |
|---|---:|---:|
| 四例开发回归 | 3/4 | 2/4 |
| C01 / C02 正例 | 通过 / 拒绝 | 拒绝 / 拒绝 |
| C03 / C04 负例 | 均拒绝 | 均拒绝 |
| 公开简报及主题正式凭证 | 未发布 | 未发布 |
| 主题预览 | 未运行 | 3 个，全部 `unverified` |

最终运行的 `theme_trial_report.json` 记录 T1/T2/T3 均为 `unverified`，`production_release_allowed=false`、`story_generation=not_run`、`media_generation=not_run`。八次调用的原始统计可由各 `model_call.json` 复算；校准复用路径及模型配置 SHA 见 `calibration_provenance.json`。

### 4.2 结论

v3 将“证据支持”和“跨领域可迁移”分开审核，成功暴露了旧审核认可的题材绑定；但**并未实现跨题材抽象目标**。此轮不能进入正式主题生成，更不能作为故事或制作输入。三个预览反而证明创作模型仍被残余身体条件牵引。`experiment-record` 的证据优先原则使这一负结果、两次技术失败和评审器自相矛盾的输出都保留在报告中，没有合并成“成功主题”。

### 4.3 尚未完成

- 尚无通过 4/4 回归并签发的 `trial_acceptance_v3`。
- 尚未解决“核心表达关系”和“可选收束方式”的界线，也未解决叙事单元 ID 被当成人物 ID 的歧义。
- 尚无第二种故事机制参考片或人工独立真值；不能宣称通用性。
